## 2. Introduction

Настоящий Master Test Plan определяет стратегию тестирования BookSphere — e-commerce платформы для печатных книг, e-books и аудиокниг. План охватывает MVP и Full-версию, функциональные модули из `task.md`, внешние интеграции и нефункциональные требования.

Scope: тестируемые функции F-01–F-36; F-37 «Smart TV и голосовые ассистенты» исключена из тестирования с обоснованием в разделе 5. Ссылки: `task.md`, `TestPlanTemplate_IEEE_829-1998.pdf`. Внутренние документы Project Authorization, Project Plan, Quality Assurance Plan, Configuration Management Plan — TBD.

Управление изменениями: через роли Test Manager, QA Lead, Product Owner, Tech Lead; изменения scope фиксируются в revision history.

## 6. Approach

- **Уровни:** компонентный, интеграционный, системный, приёмочный, нагрузочный, security.
- **Техники:** эквивалентные классы, граничные значения, таблицы решений, state transition для заказов/подписок/модерации, pairwise, risk-based, exploratory, негативное тестирование.
- **NFR по релизам:** в MVP — F-33 PCI DSS/базовая безопасность платежей и F-35 базовая производительность API < 200 мс; в Full/QA — F-34 152-ФЗ/GDPR, DDoS/SQLi, расширенный security-аудит и F-36 полная нагрузка 10 000 пользователей, SLA 99.9%, auto-scaling.
- **Внешние интеграции:** sandbox платёжных шлюзов, логистики, 1С/МойСклад, CRM, коммуникаций, контент-провайдеров; при недоступности — mock.
- **Регрессия:** после S1/S2 — полная регрессия H-функций; после S3 — целевая; перед релизом — полный регрессионный набор MVP/Full.
- **Метрики:** покрытие H-функций, pass rate, число/severity дефектов, p95 API, error rate под нагрузкой, security-находки.
- **Ограничения:** доступность sandbox, DRM-контента, платёжных тестовых карт, нагрузочного стенда.

## 7. Item Pass/Fail Criteria

**Pass**, если:
- выполнено не менее 95% тест-кейсов (допущение);
- все H-функции покрыты на 100% (допущение);
- нет открытых S1/S2; S3 — не более 5 (допущение);
- для MVP: PCI DSS-проверки пройдены, API p95 < 200 мс (200 мс из `task.md`);
- для Full/QA: нагрузка 10 000 одновременных пользователей с error rate ≤ 1% (допущение; 10 000 из `task.md`), SLA 99.9% подтверждён (99.9% из `task.md`);
- security-аудит без critical/high (допущение).

Иначе — **Fail**.

## 8. Suspension Criteria and Resumption Requirements

Приостановка, если:
- ≥ 3 дефектов S1 или ≥ 10 S2 за 24 часа (допущение);
- > 30% кейсов заблокированы сборкой (допущение);
- критичный sandbox/стенд недоступен > 4 часов (допущение);
- риск потери/порчи тестовых данных;
- critical security-инцидент.

Возобновление: фикс, smoke, проверка среды, целевая/полная регрессия по разделу 6.
